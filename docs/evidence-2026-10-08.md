# Evidence, 2026-10-08 (roadmap F1, first part)

Measured on the owner's computer (Windows 11, the real AI tool logs, a fresh hub), version 0.16.0 plus the local
commits up to the review of F0 (`fd82e69`). What a person has to do (five beginners, NVDA, a clean Windows install) is
not here yet; see "Still open".

## Contrast (WCAG 2.2)

Method: `tools/contrast-scan.js` run in the page by a headless Edge (DevTools protocol) on the Projects screen, a
project's drawer, the Helpers screen, Settings and the actions panel, in Turkish, at 1400 × 900. Every visible text
against its background: 4.5:1, or 3:1 for large text.

| Screen | Texts measured | Lowest ratio | Below the threshold |
|---|---|---|---|
| Projects | 75 | 5.14:1 (the "Found automatically" kind, 10 px) | none |
| A project's drawer | 20 | 5.75:1 (a muted helper sentence, 13.5 px) | none |
| Helpers, Settings, actions panel | (all measured) | — | none |

Not measured: the Building's canvas (drawn, not text), gradients and images behind text, hover and focus states, the
light theme (there is none). The dark theme's tokens were chosen for contrast (`public/css/theme.css`), and the scan
agrees.

## Start-up and data size

Method: `tools/perf-baseline.mjs`: the server on its own port, actions off, three runs.

| | Run 1 | Run 2 | Run 3 |
|---|---|---|---|
| Server answers | 0.69 s | 0.68 s | 0.71 s |
| First scan done (617 log files, 2.0 GB) | 6.3 s | 6.2 s | 6.4 s |
| Snapshot (first / second request) | 41 / 47 ms | 60 / 45 ms | 42 / 45 ms |
| Snapshot size | 2.85 MB | 2.85 MB | 2.85 MB |

The snapshot then holds 32 projects, 115 sessions, 346 agents and 2,364 roster items. Earlier notes said "10–15 s
on a first start with large logs" (qa/reality-check-tur2.md, A4): with 2 GB of logs it is about 6 s now. The page is
usable before the scan ends (the scan state is shown); the snapshot is light enough to load again on every change.

The snapshot's weight, measured again (roadmap F4): 3.1 MB with 155 sessions, almost all of it the roster (2,364
items; half of that their descriptions). In the page it costs about 50 ms to arrive and 12 ms to parse, and the Helpers
screen draws at most 120 rows at a time (64 ms, filtering 36 ms). Even on a computer four times slower that stays
near a quarter of a second, once per start (live changes come as patches). It is not made lighter now: the cost would
be a second request for every description, for a gain nobody would feel. It is measured again before each release
(docs/release.md).

## The built app used as a beginner (2026-10-08, afternoon)

Method: the unpacked build (`npx electron-builder --win --dir`) started with a fresh hub and data folder, driven step by
step through the DevTools protocol like a person (clicks, keys, typing; a screenshot after each step), through the
tasks a beginner meets (set up a tool, a new project, a job, the result, a second job, going back, a restart) with a real Claude Code 2.1.294 job: a new project "Kafe Menüsü
Deneme" from an idea, the job planned, built, checked and accepted, a second job in the same project (green colours),
and going back to before it. The result was a good one-page site (menu, prices, contact, opening hours, sample data
said to be sample). The job cost about 2.8 USD of Claude usage (Opus, high effort), the second about 2.0.

Found and fixed on the way (each with a test; commits 8c80e5d..95e117d):

| What a beginner met | Cause | Fix |
|---|---|---|

| Esc to close the drawer cancelled Claude's "trust this folder?" and the tool quit | focus was in the terminal, which keeps its keys | Esc in the terminal closes the open drawer first |
| No Turkish help for any of Claude Code's questions | 2.1.29x draws spaces as `ESC[1C` and lines as `ESC[r;cH`; stripped, the words ran together | cursor moves become spaces and line breaks |
| "The plan waits for your approval" before any plan existed; after the tool closed, still "being written" | the plan step had one sentence | three: being written, waiting, being cut into tasks; and "no AI works on this job now" |
| "plan only, touches no file" while the AI wrote files | Claude writes a mode change as its own `permission-mode` line, which was skipped | read |
| A notice named the session "Job J764b…8833 görevi" | the tool titles the session after its first message | the job's own words from its message |
| Second and later command questions showed no help | the command sits in a box line in 2.1.29x; with no subject every question had the same signature | box line read; a text mark tells questions apart |

| "Open in browser" said "Opening the folder in Explorer"; "0 helpers set up" on a second job | the generic texts | their own texts |

| "Go back to this point" could not be clicked with the terminal open | the drawer's bottom lay under the terminal | the drawer ends above it |

## A clean Windows: install, upgrade, uninstall (Windows Sandbox, 2026-10-08)

Method: Windows Sandbox (Windows 11 Enterprise 10.0.26100, nothing installed) running a script that installs the
published 0.16.0 installer silently (its SHA-512 equal to the release's), opens it, upgrades over it with an installer
of the current code (a local 0.17.0-rc.1 build, not published), opens it again and uninstalls.

| Step | Result |
|---|---|
| 0.16.0 installs (14 s), desktop and Start menu shortcuts | passed |
| 0.16.0 first start: server ready, page loaded, hub made | passed |
| Upgrade (19 s): version 0.17.0, the hub kept, one uninstaller | passed |
| The upgraded app starts: server ready, page loaded, the first-start screen ("Bir fikrin mi var?") | passed |
| Uninstall: program, shortcuts and uninstall entry gone, nothing left running | passed |
| Kept on purpose: the data folder and the hub (deleteAppDataOnUninstall: false) | as designed |

One check of the script failed on its own mistake (Windows reports the version as 0.16.0.0); fixed in the script.

## Accessibility pass (axe-core and a keyboard walk, 2026-10-08)

Method: in the built app (1400 × 900, Turkish, data loaded), axe-core 4.10.2 with the WCAG 2.1 A and AA rules on the
Building, Projects, Helpers, Feed and Settings and over the project drawer, the tools panel, New project, the guide and
the command palette; and on each, a walk with Tab that reads every stop from the accessibility tree (the role and
name a screen reader says) and checks a visible focus ring.

Found and fixed: Tab left the tools panel for the page behind (it counted the fields of a closed fold), so Esc then
did nothing; small text under 4.5:1 (a project's initials 4.32, the roster's "Other" 4.18, the feed's meta 3.31–4.37
with its dimmed rows); the waiting chip and the Building's recent list as empty, nameless elements until data arrived.

After the fixes: no violation on any screen or dialog; every Tab stop has a name and a visible focus ring; each dialog
keeps Tab inside (the drawer 5 stops, the tools panel 5, New project 6, the guide 10).

Not covered by this pass: what NVDA says when a job's state changes (live regions), reading order inside the drawn
Building, and how the terminal reads. These need a person with NVDA.

## Idle memory and a hidden window (2026-10-09, plan D5)

- **Measured by** `tools/electron-qa.ps1` run 3 (the packaged app, its window hidden, the server ready, 20 s with
  nothing happening; a temporary hub with no projects): 5 processes, **692 MB** working set in all, **558 MB** private;
  per process 226, 168, 128, 112 and 57 MB. The QA's ceiling (1 GB) only catches a leak; the next release puts its
  numbers next to these.
- **What waits while the window is hidden** (minimized, covered or in the tray; `public/js/whileVisible.js`): the
  clock, the "12 s ago" times, the screens' drawing, the open project's drawer and the tools wizard's check. Each runs
  once when the window shows again. The workshop picture already stopped while hidden. The notifications, the window
  title and the usage-limit check go on: they are what a hidden window is for. The server keeps reading the logs, as
  before.
- The QA's hidden window turns Electron's background throttling off, so the page counts as visible there: the numbers
  above are of a page that draws.
