## PlayerController.cs (2D, Input System)

Save as `Game/Assets/Scripts/PlayerController.cs`.

```csharp
using UnityEngine;
using UnityEngine.InputSystem;

// Moves a 2D player left and right, and jumps while it touches something below it.
[RequireComponent(typeof(Rigidbody2D))]
public class PlayerController : MonoBehaviour
{
    [SerializeField] float moveSpeed = 6f;
    [SerializeField] float jumpSpeed = 11f;
    [SerializeField] LayerMask groundLayers = ~0;

    Rigidbody2D body;
    float moveInput;
    bool jumpQueued;

    void Awake() => body = GetComponent<Rigidbody2D>();

    // Input is read every frame
    void Update()
    {
        var keyboard = Keyboard.current;
        if (keyboard == null) return;
        moveInput = 0f;
        if (keyboard.aKey.isPressed || keyboard.leftArrowKey.isPressed) moveInput -= 1f;
        if (keyboard.dKey.isPressed || keyboard.rightArrowKey.isPressed) moveInput += 1f;
        if (keyboard.spaceKey.wasPressedThisFrame) jumpQueued = true;
    }

    // Physics runs at a fixed rate
    void FixedUpdate()
    {
        Vector2 velocity = body.linearVelocity;
        velocity.x = moveInput * moveSpeed;
        if (jumpQueued && body.IsTouchingLayers(groundLayers)) velocity.y = jumpSpeed;
        jumpQueued = false;
        body.linearVelocity = velocity;
    }
}
```

Notes: values set in the Inspector override the numbers in the code. `IsTouchingLayers` is a simple ground test
for a prototype (touching a wall also counts); replace it with a ground check below the feet later. Unity versions
before 6 call `linearVelocity` `velocity`.

## Checks without the editor window

Close the Unity Editor first (batch mode cannot open a project that is already open). Find the editor version in
`Game/ProjectSettings/ProjectVersion.txt`.

```powershell
$unity = "C:\Program Files\Unity\Hub\Editor\<version>\Editor\Unity.exe"
$p = Start-Process $unity -ArgumentList '-batchmode -nographics -quit -projectPath "C:\path\to\project\Game" -logFile "C:\path\to\project\unity-check.log"' -Wait -PassThru
$p.ExitCode
```

Exit code 0 means the project opened and compiled. Search the log for `error CS` to find script errors.

Edit Mode tests (Unity Test Framework): same command, but replace `-quit` with
`-runTests -testPlatform EditMode -testResults "C:\path\to\project\test-results.xml"`. A non-zero exit code means a
test failed or the run broke; the XML file lists each test. Keep the log and results files out of git.

## Common errors

| Message or symptom | Cause and fix |
|---|---|
| `InvalidOperationException: You are trying to read Input using the UnityEngine.Input class, but you have switched active Input handling to Input System package` | Old-style input code (`Input.GetAxis`) in a project that uses the Input System. Use the Input System API as in the script above. Switching Player Settings > Active Input Handling to "Both" also works (ask first; the editor restarts). |
| "All compiler errors have to be fixed before you can enter playmode" | A script does not compile. Read the first red error in the Console; it names the file and line. |
| "Can't add script component ... the script class cannot be found" | Compile errors, or the class name differs from the file name. |
| `NullReferenceException: Object reference not set to an instance of an object` | A field is empty: an Inspector slot not filled, or `GetComponent` found nothing. Double-click the error to see the line. |
| The player does not move | Script not on the object, Body Type is Static, or the Inspector value of the speed is 0 (Inspector values win over code). |
| Objects fall through the floor | The floor has no collider, or 2D and 3D physics are mixed (a Rigidbody 2D needs 2D colliders). |
| The player tips over | Freeze Rotation Z on the Rigidbody 2D. |
| Everything is pink | A material or shader does not match the render pipeline (URP). Use URP materials, or Window > Rendering > Render Pipeline Converter. |
| Missing references after moving files | Files were moved in File Explorer. Move them back, then move them inside Unity's Project window. |
| Scene changes vanished | They were made during Play mode. Stop Play first, then edit. |
| Merge conflicts in scene files | Two people edited the same scene. One person per scene at a time; put shared objects in prefabs. |
| No autocomplete in the code editor | External Tools not set, or project files are stale: Preferences > External Tools > Regenerate project files. |

## Next steps that stay small

- Restart: with `using UnityEngine.SceneManagement;` at the top,
  `SceneManager.LoadScene(SceneManager.GetActiveScene().buildIndex);` reloads the current scene.
- Camera follow: a short script that moves the camera toward the player in `LateUpdate`, or the Cinemachine package
  later (installing a package needs a yes).
- Keep game rules (score, health, win condition) in plain C# classes; they are easy to test in Edit Mode.

## Sound

Editor steps (user): select `Player`, Add Component > Audio Source, Play On Awake off. Music: an empty object `Music`
with an Audio Source, a music clip, Loop and Play On Awake on.

```csharp
using UnityEngine;

// Plays a short sound when asked. Put it on the same object as an AudioSource.
[RequireComponent(typeof(AudioSource))]
public class SoundPlayer : MonoBehaviour
{
    [SerializeField] AudioClip jumpClip;
    AudioSource source;

    void Awake()
    {
        source = GetComponent<AudioSource>();
    }

    public void PlayJump()
    {
        if (jumpClip != null) source.PlayOneShot(jumpClip);
    }
}
```

Call `GetComponent<SoundPlayer>().PlayJump();` from `PlayerController` when the jump starts. No sound: Mute Audio is on
in the Game view, the clip slot is empty, or the Audio Source is disabled.

## Saving and loading

For a high score or a setting, `PlayerPrefs` is enough:

```csharp
PlayerPrefs.SetInt("highScore", score);
PlayerPrefs.Save();
int best = PlayerPrefs.GetInt("highScore", 0); // 0 when nothing was saved yet
```

For more data, write a small JSON file in the folder Unity gives for saves (`Application.persistentDataPath`):

```csharp
using System.IO;
using UnityEngine;

[System.Serializable]
public class SaveData
{
    public int score;
    public float playerX;
}

public static class SaveSystem
{
    static string FilePath => Path.Combine(Application.persistentDataPath, "save.json");

    public static void Save(SaveData data)
    {
        File.WriteAllText(FilePath, JsonUtility.ToJson(data));
    }

    // Returns a fresh SaveData when there is no file or it cannot be read
    public static SaveData Load()
    {
        if (!File.Exists(FilePath)) return new SaveData();
        try { return JsonUtility.FromJson<SaveData>(File.ReadAllText(FilePath)); }
        catch (System.Exception) { return new SaveData(); }
    }
}
```
Players can edit save files: never trust them online. Test by saving, stopping Play mode, starting again and loading.

## A simple menu

1. New scene `Menu` (File > New Scene, save in `Assets/Scenes`). Hierarchy > right click > UI > Button (this creates a
   Canvas and an EventSystem). Rename it `PlayButton`, change its text to "Play". Add a second button `QuitButton`.
2. Create `Assets/Scripts/MenuButtons.cs` and put it on an empty object named `MenuController`:

```csharp
using UnityEngine;
using UnityEngine.SceneManagement;

public class MenuButtons : MonoBehaviour
{
    // Name of the scene to open; it must be in the build list
    [SerializeField] string gameSceneName = "SampleScene";

    public void OnPlay()
    {
        SceneManager.LoadScene(gameSceneName);
    }

    public void OnQuit()
    {
        Application.Quit(); // does nothing inside the editor, works in a build
    }
}
```

3. Select each button: in the On Click () list press +, drag `MenuController` in, and choose `MenuButtons > OnPlay` (or
   `OnQuit`).
4. File > Build Profiles: add both scenes to the scene list (Add Open Scenes while each is open), with `Menu` first.
   A scene that is not in the list cannot be loaded in a build ("Scene ... couldn't be loaded because it has not been
   added to the build settings").

## Making a build (Windows)

1. Project Settings > Player: Company Name, Product Name, Version. Save the project.
2. File > Build Profiles, choose Windows, check the scene list, press Build. Choose a folder outside `Assets/`, such as
   `Builds/Windows` (git-ignored, see the `.gitignore` above). The first build takes several minutes.
3. Open the built `.exe` and play for a minute (input, resolution, sound and saving can differ from the editor). To
   share the game, zip the whole build folder (the `.exe` and the `_Data` folder together).
4. A greyed-out Build button means a compile error: fix the Console first. A build that fails on editor-only code needs
   it wrapped in `#if UNITY_EDITOR` and `#endif`. Sound or saves that only work in the editor use a hard-coded path:
   use `Application.persistentDataPath` or a clip slot instead.
